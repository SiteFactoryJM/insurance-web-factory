# 프리미엄 보험 상담 페이지와 DIY 제작 도구 디자인 조사

조사일: 2026-09-08. 금융·보험·법률·프리미엄 서비스의 공식 사이트를 웹 검색한 뒤 1440 × 1000 화면과 실제 렌더링 스타일을 확인했다. 아래 수치는 해당 화면의 관찰값이며 브랜드 전체 디자인 가이드를 뜻하지 않는다. 구현 제안은 이 관찰을 한국어 보험 상담 페이지에 적용한 판단이다.

## 디자인 방향

첫 화면은 완성된 상담 페이지의 대표 예시로 보여준다. 페이지를 만드는 조작은 별도의 DIY 화면에서 한다. 고급스러움은 낮은 채도의 색, 제목과 본문의 분명한 위계, 넓은 여백, 사진의 크롭과 정보 배치로 만든다. 섹션은 배경색 수를 늘리는 대신 배열·선·간격·사진 비율로 구분한다.

기존 화면에서 반복되던 굵은 고딕 제목과 비슷한 3열 콘텐츠의 조합을 줄이고, 각 섹션의 목적에 맞는 구조를 제공한다. 사용자 이미지의 푸터처럼 연락처와 등록 정보를 끝까지 읽기 좋게 정리한다.

## 구현에 적용할 다섯 가지 원칙

1. **한 계열 안에서 명도와 면적을 조절한다.** 대표 예시는 아이보리 `#F5F2EA`, 따뜻한 흰색 `#FBFAF7`, 짙은 초록 `#183D36`, 회색 텍스트 `#59635E`를 기본 방향으로 한다. 보조 금빛은 작은 번호나 구분선에 제한한다. 실제 토큰은 글자 대비 검증 후 확정한다.
2. **제목과 본문의 서체 역할을 나눈다.** 제목은 한글 명조 계열 400~500, 본문·메뉴·입력은 읽기 쉬운 고딕 계열을 쓴다. 본문 18px와 고지 최소 16px를 유지한다. 제목 크기, 행간, 최대 너비를 함께 조절해 모바일에서도 문구가 잘리지 않게 한다.
3. **내용에 따라 섹션 구조를 바꾼다.** 첫 화면은 큰 문장과 인물 사진, 소개는 여백 있는 편집 배치, 상담 분야는 번호가 있는 목록, 상담 순서는 타임라인, FAQ는 펼침 목록을 기본 예시로 조합한다. 배경이 같더라도 상단 선, 작은 섹션 번호, 배열 차이가 경계를 만든다.
4. **버튼은 단순하고 행동은 명확하게 쓴다.** 주요 행동은 채운 직사각 버튼 하나에 집중한다. 보조 행동은 가는 테두리 또는 화살표 링크를 사용한다. 대표 예시의 상담 행동과 DIY 도구의 편집·저장 행동이 섞이지 않게 화면을 분리한다.
5. **푸터를 신뢰 정보의 마지막 접점으로 만든다.** 좌측 브랜드·소속·등록 정보·주소와 우측 전화·이메일·상담 시간을 묶고, 구분선 아래 고지를 배치한다. 모바일에서는 읽는 순서대로 세로 배치한다. 고지 문구를 장식처럼 옅게 처리하지 않는다.

## DIY 패턴 선택 설계

아래는 독립 선택이 가능한 구조의 제안이다. 출시한 옵션의 실제 이름·개수는 구현을 기준으로 한다. 미리보기 썸네일은 색보다 각 구조의 차이를 보여줘야 한다.

| 편집 대상 | 제공할 구조 예시 | 편집 데이터 |
| --- | --- | --- |
| 첫 화면 | 문장+사진 양단 / 사진 중심 / 중앙 정렬 | PC·모바일 제목과 소개, 주요/보조 CTA, 이미지와 대체 텍스트 |
| 설계사 소개 | 편집형 인물 소개 / 경력 정보 패널 / 짧은 소개문 | 이름, 직함, 소속, 소개 제목·본문, 확인 가능한 이력 |
| 상담 분야 | 번호가 있는 행 / 분할 패널 / 단정한 그리드 | 실제 취급 가능한 분야, PC·모바일 설명 |
| 상담 순서 | 가는선 타임라인 / 번호 순서 목록 | 단계별 제목·설명 |
| FAQ | 양단 질문 목록 / 중앙 펼침 목록 | 질문, PC·모바일 답변 |
| 푸터 | 양단 연락처 / 중앙 브랜드 / 정보 열 | 브랜드 표시명, 소속, 사업자·등록 정보, 주소, 전화, 이메일, 상담 시간, 고지 |

내용 입력에는 `예시 사용`을 제공한다. 예시 사용을 선택하면 눈앞에 보이는 샘플 문구를 편집값으로 실제 채워 넣고, 사용자가 이어서 수정할 수 있게 한다. 미작성 항목을 실제 경력·후기·등록 정보처럼 보이게 자동 보충하지 않는다. 예시 인물과 고지의 성격은 대표 페이지와 결과물에서 계속 구분한다.

PC·모바일 문구는 같은 폼 안에서 각각 입력하며 현재 글자 수와 한도를 표시한다. 기존 기준인 메인 제목 40/24자, 메인 설명 120/60자, 소개 제목 40/24자·본문 400/100자, 분야·절차 설명 120/48자, FAQ 답변 240/80자를 재사용한다. 모바일 원문을 비웠을 때 PC 원문을 사용하는 동작도 분명하게 안내한다. 보험 고지·개인정보 안내는 모바일용으로 축약하지 않는다.

## 제작자가 다시 사용할 저장물

편집 재개와 개인별 사이트 제작에는 **구조화된 JSON 파일**을 기본 결과물로 사용한다. 선택한 패턴·팔레트·PC/모바일 원고·이미지 정보·푸터·고지와 파일 버전을 담고, 같은 DIY 화면에서 다시 불러와 편집할 수 있어야 한다. 데이터 다운로드는 사용자가 명시적으로 누른 시점에만 일어난다. 상담 체험 입력은 제작 데이터에 섞거나 저장하지 않는다.

**PDF 저장**은 사람이 원고와 선택 사항을 확인하는 보조 결과물이다. 브라우저 인쇄를 사용하는 경우 버튼을 누르면 인쇄 창에서 PDF로 저장한다는 점을 안내하고, DIY 조작 버튼을 인쇄에서 제외한다. 긴 원고와 푸터 고지가 페이지 경계에서 잘리지 않아야 한다. JSON과 PDF의 역할을 구분하면 사용자는 시안을 확인할 수 있고 제작자는 원본 데이터를 재사용할 수 있다.

DIY 데이터는 일반 site.json 원본으로 반영하기 전 검증을 거친다. 내보낸 시안 자체가 게시 승인을 뜻하지 않으며, 초안/noindex와 예시 상태를 유지한다. 설계사별 운영 원본은 계속 `sites/<id>/site.json`이다.

## 조사 증거와 한계

- 캡처·관찰값: `artifacts/premium-reference/`의 `*-hero.png`, `*-content.png`, `observations.json`.
- 재현 스크립트: `artifacts/premium-reference/capture.mjs`.
- in-app Browser 연결을 시도했지만 사용 가능한 브라우저 목록이 비어 있어 프로젝트 Playwright로 공개 페이지를 확인했다.
- 외부 페이지의 미디어 로딩과 스크롤 애니메이션 때문에 일부 콘텐츠 캡처에서 이미지가 비어 있다. 빈 화면을 디자인 의도로 해석하지 않았다. Coutts는 선명하게 확인된 상단 화면, Aman은 확인된 사진 배치와 렌더링 스타일을 근거로 했다. 광고·동의창은 가능한 범위에서 닫은 뒤 관찰했다.
- 특정 디자인이 상담 전환율을 높인다는 수치 주장은 하지 않는다. 이 문서는 공식 페이지의 관찰과 이번 서비스에 대한 적용 판단이다. 외부 로고·사진·독점 서체를 서비스 자산으로 재사용하지 않는다.
