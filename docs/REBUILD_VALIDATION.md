# Clear Human 리빌딩 검증 기록

검증일: 2026-09-17. 브랜치: `feat/clear-human-user-first-20260917`.

## 이번 라운드에서 바꾼 것

1. Figma `CH2/Navy/*` 컴포넌트 수치를 `src/render/clear-human-styles.ts`에 정본으로 옮기고,
   고객 첫 화면에 `Agent Details` 카드를 추가했다. 본문 글꼴을 Noto Sans KR로 바꿨다.
2. 제작 화면의 1단계를 `화면 구성 · 색상 + 문구 선택` 한 화면으로 합쳤다. 구성이나 색상을 바꿔도
   고른 문구는 유지된다.
3. 모든 단계에서 여는 전체 화면 미리보기와 ✕ 닫기 버튼을 넣었다. Esc로도 닫힌다.
4. `초안 저장 및 시연`(입력값 그대로 큰 화면 + 브라우저 보관)과 `파일로 내보내기`(압축 파일)를
   분리했다.
5. 고객·제작 화면 전반의 개발 용어(JSON, ZIP, 렌더러, 검색 비노출, 제작 파일 등)를 사용자 표현으로
   바꿨다.
6. 자유 편집(`/studio/advanced`)과 그 번들·테스트를 제거해 제작 경로를 `/studio` 하나로 모으고,
   나가는 길을 메인(`/`) 하나로 통일했다.
7. 가로 768px 미만에서는 제작 화면 대신 안내만 표시하고, 고객 화면의 제작 진입 버튼도 감춘다.

## 자동 검증

- `npm run check`: 사이트 1개, 도메인 0개, 오류·경고 0개, 타입 검사 성공, 202개 단위 테스트 통과.
- `npm run test:e2e`: 25개 Playwright 시나리오 전체 통과(약 1분 30초). 30개 구성·색상 조합, 고객
  페이지, 3단계 제작 화면, 768/1024/1440px, 200% 글자 확대, 접근성, 실제 압축 파일 다운로드를
  포함한다.
- 전체 실행 중 두 가지를 발견해 고쳤다. 첫째, 마지막 스타일 레이어의 `.button` 규칙이 카카오
  버튼 색을 덮어 대비가 1.45:1까지 떨어졌다. 채널 색 규칙을 같은 레이어 뒤로 옮겼다. 둘째,
  1001~1080px 구간에서 제작 화면의 2열 격자가 화면을 넘겼다. 한 열 전환 기준을 1080px로 올렸다.

## 손으로 확인한 흐름

- 02 실제 정보에 이름·직함·소속·전화·상담 시간·오픈채팅 주소를 입력했다.
- 03에서 `초안 저장 및 시연`을 눌러 입력값이 그대로 들어간 전체 화면을 확인하고 ✕로 닫았다.
- 확인란 세 개를 체크하고 `파일로 내보내기`를 눌러 실제 압축 파일이 내려받아지는 것을 확인했다.

## 실제 압축 파일 검증

- Chromium에서 실제 `download` 이벤트를 받아 압축 파일을 열었다.
- 루트 파일은 인쇄본 1개와 작업 파일 1개뿐이다.
- 작업 파일 v2, `clear-human-v1`, 작업 번호, `draft`, `noIndex`, 문의 폼 비활성을 확인했다.
- `pdf-lib`으로 인쇄본을 열고, PDF.js로 모든 페이지의 텍스트를 추출해 담당자 이름·소속·전달
  안내 한글을 확인했다. 자동 E2E에서도 같은 항목을 검사한다.

## 반응형·접근성

Playwright가 고객 페이지는 320, 360, 390, 768, 1440px에서, 제작 화면은 768, 1024, 1440px에서
수평 오버플로가 없는지 확인한다. 390px 제작 화면에서는 안내 화면만 보이는지 검사한다. 두 화면
모두 WCAG 2 A/AA·2.1 AA·2.2 AA axe 규칙을 통과한다. 고객 미리보기의 전화·오픈채팅은 제작
화면 안에서 실행되지 않는다.
